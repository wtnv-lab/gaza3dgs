The 3D Gaussian splatting were generated by UTokyo, using LumaAI based on the video footages by Al Jazeera. In addition, web apps were created using the Luma WebGL Library and Three.js.

## Replacing a scene with a KIRI 3DGS export

This project can also use 3DGS data exported from KIRI. The practical flow we used for `Premature Babies in Improvised Care` is below.

### 1. Find the asset URLs from a KIRI share page

Given a KIRI share URL such as:

```text
https://www.kiriengine.app/share/3dgs?taskId=2036241175110746112
```

open the page source and extract:

- `splatUrl`
- `cameraUrl`

In practice, these are embedded in the page data payload and point to files on CloudFront.

### 2. Download the `.splat` and `cameras.json`

You can do this manually, or use the helper script added to this repo:

```bash
tools/kiri_to_spz.sh \
  "https://www.kiriengine.app/share/3dgs?taskId=2036241175110746112" \
  baby01
```

This writes:

- `ply_spz/baby01.spz`
- `ply_spz/cameras/baby01.json`

Manual example:

```bash
mkdir -p /tmp/kiri-work
curl -L --max-time 60 -o /tmp/kiri-work/model.splat "KIRI_SPLAT_URL"
curl -L --max-time 60 -o /tmp/kiri-work/cameras.json "KIRI_CAMERA_URL"
```

### 3. Check whether the KIRI `.splat` is actually a compressed PLY

KIRI's `3DGS.splat` may not be an antimatter-style `.splat`. In our case it was a PlayCanvas compressed PLY with a `.splat` extension.

Quick check:

```bash
xxd -l 64 /tmp/kiri-work/model.splat
```

If the header starts with `ply`, treat it as compressed PLY.

### 4. Convert compressed PLY to plain PLY

We used `@playcanvas/splat-transform`.

```bash
mkdir -p /tmp/kiri-spz-tools
cd /tmp/kiri-spz-tools
npm install @playcanvas/splat-transform spz-js

cp /tmp/kiri-work/model.splat /tmp/kiri-work/model.compressed.ply
/tmp/kiri-spz-tools/node_modules/.bin/splat-transform \
  -w /tmp/kiri-work/model.compressed.ply \
  /tmp/kiri-work/model.ply
```

If `splat-transform` fails with a message like `Invalid .splat file`, the file is likely not a true `.splat` and should be handled as above.

### 5. Convert the PLY to `.spz`

Example with `spz-js`:

```bash
cd /tmp/kiri-spz-tools
node --input-type=module <<'EOF'
import { readFile, writeFile } from "node:fs/promises";
import { loadPly, serializeSpz } from "spz-js";

const ply = await readFile("/tmp/kiri-work/model.ply");
const gs = loadPly(ply.buffer);
const spz = serializeSpz(gs);
await writeFile("/tmp/kiri-work/model.spz", Buffer.from(spz));
EOF
```

### 6. Place the generated files in this repo

- Copy the generated `.spz` into `ply_spz/`
- Copy the downloaded `cameras.json` into `ply_spz/cameras/`
- Use the final production filenames you want to reference from `js/index.js`

Example:

```text
ply_spz/baby01.spz
ply_spz/cameras/baby01.json
```

### 7. Update the scene definition in `js/index.js`

Replace the old `iframe` scene entry with an `spz` entry:

```js
{
    title: "Premature Babies in Improvised Care",
    type: "spz",
    assetPath: "./ply_spz/baby01.spz",
    cameraPath: "./ply_spz/cameras/baby01.json"
}
```

If the model orientation is wrong, add a scene-local `modelRotation` override:

```js
modelRotation: { x: 0, y: 0, z: 0 }
```

This is useful because the viewer currently applies a default rotation to SPZ scenes, and some KIRI exports may need a different orientation.

### 8. Verify the result

- Confirm the `.spz` opens successfully
- Confirm the camera path plays correctly
- Confirm the model orientation is correct in the browser

For quick local validation of the generated asset itself, `spz-js` can load the `.spz` and report the point count before wiring it into the app.
